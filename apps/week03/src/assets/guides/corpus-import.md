# 新语料怎样进入第三周演示

2026-09-24。使用已有“语料库管理”入口，无需修改网页、检索算法或重新部署。该入口读JSON／JSONL，不直接做PDF的OCR。

## 本地和线上是同一种导入操作

1. 本地：启动课堂后打开 `http://127.0.0.1:8767/week03/`。线上：打开 https://lyzhackjp.github.io/pku-aihis/week03/ 。
2. 点击右上角“语料库管理”，在“追加语料（可多选）”中选择语料JSON文件。
3. 推荐使用教师已准备的 `全部公开语料.vectors.json`。这个文件同时含正文、出处和384维向量，约27.9MB、2686条，不是仅有数字的向量文件。无须先导入JSONL，也无须同时选择同内容的11个分包。
4. 等待显示“新增2686条；累计2713条”，并核对向量覆盖2713条。原来的27条课堂材料保留。
5. 关闭管理窗口，在D07关键词、D08向量、D09混合、D11全文、D12近邻及D13 RAG中使用当前语料。可用 `Rabbit`、`justice`、`radiocarbon` 等实际存在的词先试检索；D13可问“兔子从哪里取出表？只根据本次片段回答并引用编号”。

只有JSONL也可以直接追加，用于关键词和全文检索。向量检索需要兼容的向量包；同编号配套向量可在以后补齐，重复选择相同内容会跳过，不会增殖。单次可多选，合计上限130MB。

线上选择本机文件只是让当前浏览器读取，导入本身不会把文件传到GitHub，也不会改变其他同学的网页。分享给同学时，每人保存同一份导入文件并各自选择；无需Git操作。不要要求学生上传到仓库后才能使用。

## 查询与问答

文件中的正文向量已算好，新输入问题仍需编码。教师本机使用已下载的MiniLM；线上没有连接本机编码器时，浏览器首次可能下载约118MB的兼容模型。已有预计算查询可以直接排序。无法下载时，先演示关键词检索，或切回本机课堂。

D13新增材料问答按“检索→确认上下文→构建请求→调用生成”进行。选择本机模型需运行课堂模型服务；选择外部API时，在“模型接入”填写地址、模型和Key。仅导入语料不会调用生成服务，点击生成时才会发送问题和选入的上下文。网络／跨域受限时可用教师本机桥接或直接打开本地网页。

线上可以查看公共来源链接；本地核验原件入口只在配置了对应原件的教师本机提供。导入向量JSON不等于把整部原书PDF一起上传。

## 页面刷新与共同默认库

当前导入保存在这一张页面的内存中：翻页保留，刷新、关闭或重新打开后恢复默认27条库。每次上课重新选择同一个文件即可；已保存的应用示例不会因导入自动重写。

如果以后希望所有人打开网站就自动载入新库，可另做“数据包默认化”：合并数据并更新默认 `assets/data/corpus.json`，调整固定27条的核验与外部工具示例范围后再部署，不必重写检索算法。但本课部分神经稀疏、多模态、保存答案和外部应用示例依赖固定课堂快照，不能把替换一份JSON说成所有工具都自动支持新库。本次采用手动追加，不变更默认库。

## AnythingLLM等外部应用

浏览器内的语料与外部应用数据库是两个存储位置。要在AnythingLLM中真正加入材料，打开教师本机 `http://127.0.0.1:3301`，进入“第三周史料检索课堂”，上传带出处TXT或原PDF，在文档管理中移入工作区（Move to Workspace），再保存并嵌入（Save and Embed）。等待处理完成后在应用内提问，或回D14展开“已安装：在本机重跑”。应用导入流程可参照[官方集成指南](https://milvus.io/docs/use_milvus_in_anythingllm.md)。

优先上传已OCR的TXT，避免将尚无文字层的扫描PDF误当作可检索正文。网页MiniLM向量包不能直接当作AnythingLLM的Qwen嵌入库；上传文本后由它自己的嵌入模型重新编码。应用还会自行切块，不能假定与网页记录一一对应。D14现有桥接指向上述已有工作区；另建工作区时须同步修改本机配置中的工作区标识。

Elasticsearch／OpenSearch、Tantivy及Chroma／Qdrant／Milvus在本课有各自固定快照和重跑适配；其中有的会从课堂文件重新建索引，有的还依赖预计算稀疏权重。手动向某个数据库写新数据，不能保证网页重跑就使用它。本次保持它们为分类示例，大库检索主要放在D07—D13；如后续要扩展某个应用，再单独配置其数据源并验收。
