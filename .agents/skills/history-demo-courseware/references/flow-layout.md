# 四栏流程版式（flow4）

来源：第三周助教 kwadraten 的改版（pku-aihis 提交 63db0c1，“将旧的分区布局变为流程式布局”，2026-09-24）。D01—D32 由“上：可折叠说明＋下左：面板＋下右：效果”三段式，改为按流程从左到右的多列布局；旧的 process-explainer、lab-grid 等组件随之删除。实现见 `apps/week03/src/components/lesson-lab/lesson-lab.tsx` 的 `flowShell()` 与 `src/global/app.css` 的 `.flow-*` 样式。

## 结构

```
┌ 本页问题（粗体） ─ 01·步骤 → 02·步骤 → 03·步骤 → 04·步骤   ← 步骤轨，随操作点亮
├──────────┬──────────┬──────────┬──────────┐
│01 列标题  │02 列标题  │03 列标题  │04 列标题  │ ← 编号＋标题，蓝色下划线，列内滚动时吸顶
│┃为什么    │┃为什么    │┃为什么    │┃为什么    │ ← why：一两句，说明这一步做了什么、可能出什么错
│真实控件   │中间结果   │可视化     │结果与代入 │ ← body：控件、中间产物、图、公式代入
└──────────┴──────────┴──────────┴──────────┘
  动手观察：……                                    ← 一句操作提示，取自讲义练习
```

- 每一列是流程中的一步，从输入到结果从左到右排；步骤名与 `steps` 字段一致，3—6 列，默认 4 列。
- 列里放真实控件或真实中间结果，不放折叠的长说明；讲解放进 `why` 一两句和教师备注。
- 改动左列的输入，右边各列同步重算（输入→中间产物→结果联动）。
- 步骤轨 `active` 标当前操作所在步骤，`done` 标已完成步骤（如 D13、D21、D24 随进度点亮）。
- 宽屏时各列等高、列内滚动，动手观察条固定在底部；窄屏（≤760px）改为单列整页滚动，不在面板里嵌小滚动区。
- 运行模式标签逐页保留；构造的输出与实算的输出在同一页时分列写明。

## 适用与不适用

适用：计算（系数、距离、排序、指标）、处理流程（切分、检索、生成、核对）、判断流程（定级、归并）。
不适用：封面结语（hero）、脉络回顾与论文结果（diagram）、需要整块应用界面的工具实操（workbench）、贯穿页（through）与概念页（concepts）。

## 写列时自查

1. 第一列是不是学生能改的输入？
2. 中间列是否展示了“机器真正产生的中间结果”（集合、交集、表、候选）而不是文字解释？
3. 最后一列的数值是否给出代入式，能和讲义图对上？
4. `why` 是否正向表述、一两句以内？
5. 动手观察是否来自讲义练习，并说明要观察的变化？

## 原型实现

`templates/prototype/deck-core.js` 的 `Deck.flowShell(page, columns, rail)` 与第三周 `flowShell` 参数一致：`columns = [{title, why, body}]`，`rail = {active, done}`；问题、步骤、动手观察取自页表。重绘用 `Deck.rerender()`，保留输入框焦点与光标位置。
